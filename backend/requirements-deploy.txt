# Nutri-AI backend — hosted deployment dependencies.
#
# This is requirements.txt WITHOUT torch/torchvision/ultralytics/timm.
#
# Why a second file instead of a flag: the torch CPU wheel plus its transitive
# deps is ~2.5 GB installed. On a 512 MB Render instance that is not a slow
# build, it is a failed one — and none of it would ever be loaded, because the
# hosted pipeline offloads the one stage that needs torch to the classifier
# Space (CLASSIFIER_URL) and takes the guarded heuristic path for the rest.
#
# Every torch import in the backend is wrapped in try/except with a classical-CV
# fallback (classify.py, depth.py, detection.py, calorieclip.py,
# food_segmentation.py, indian_food_classifier.py), so absence is a supported
# state, not a broken one. The pipeline reports engine="heuristic" for those
# stages and still returns a full answer for every meal photo.
#
# Local development still uses requirements.txt — keep the two in sync when
# adding a non-torch dependency.
